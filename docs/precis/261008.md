# Precis — 2026-10-08

## Key points from the day

### `EgoItem.egoHasIgnoreType` checked against `ego_has_ignore_type` in `obj-ignore.c`

`egoHasIgnoreType` answers whether an ignore category is valid for an ego by walking the kinds it may apply to and the
`qualityMapping` table. It had no Javadoc, and the table it reads, `ObjectInfo.qualityMapping`, and the `possItems`
field it walks were undocumented or described wrongly. The check found no difference from C, with all 37 table rows in
C's order and the same case-sensitive substring match against the kind's name. `EgoHasIgnoreTypeTest` pins the
empty-identifier rows, the named identifiers, the Bow/Crossbow case split and the dragon-armour groups against figures
worked from C. Whatever ports the options menu next can rely on this function to offer the same categories for each ego
as C does.

### `ItemObject.isKnownArtifact` and `ObjectUtils.objIsKnownArtifact` checked against `object_is_known_artifact` and
`obj_is_known_artifact`

C has two known-artifact tests, one reading only the known half (`obj-knowledge.c`) and one that also requires the real
object to be an artifact (`obj-util.c`), and `isArtifact` equals neither. The first check found `objIsKnownArtifact`
declared as an instance method on a class with no instances; you made it static and both then matched C clause for
clause. `KnownArtifactTest` pins the one input where the two disagree (a known half with an artifact on a real object
with none), and the Javadoc on both methods and on the `artifact` and `known` fields says which C function each stands
for. The sites that need these tests, `object_desc` and `compare_items` among them, can now be ported without reaching
for `isArtifact`; the known half still has no artifact setter, so `object_touch` has to add one.
