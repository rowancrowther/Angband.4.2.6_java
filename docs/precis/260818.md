# Precis — 2026-08-18

## Key points from the day

### `timedGradeEq` took three passes, and each one was the same mistake in a different place

A timed effect is one counter, but the status the player sees is a band of it — stunning runs Stun, Heavy Stun, Knocked
Out — and `player_timed_grade_eq` answers which band the counter is in. The port searched every band whose maximum
covered the value instead of stopping at the first, so a lightly stunned player answered true to "Knocked Out", and the
zero guard that C opens with had been dropped because the map is pre-populated with a zero for every effect. Both are
fixed, and the loop now returns on the first covering band whether it matched or not. It is the predicate lesson again
from a different angle: the walk was right and the stopping condition was wrong, which is exactly the shape that reads
plausibly and compiles.

### The pre-commit review found a silent stub, and everything else checked out

Twelve files were read against the C original before committing. `ImmutableFlag` was the only real hazard — every method
returned false, null or zero with no Javadoc and no stub marker, in a repo where forty-odd unfinished methods are all
labelled. It has since been deleted. Everything substantive verified clean: all eighteen `StatTables` arrays are
element-for-element identical to `player-calcs.c`, the fifty-three `TimedEffect` rows match `list-player-timed.h` in
order and flags, and `decreaseTimeouts`, the curse tick, the digestion block and `decTimed` are exact ports. The audit
habit from the 16th paid off again: the fault it found was the one that would never have thrown.

### `FlagView` gave the port back something C had and Java did not

C passes flag arrays as `const bitflag *` wherever a function only reads them, so the compiler enforces read-only at
every call site; Java handed callers a mutable `Flag` and relied on intent. The new interface restores that, and the
day's work was drawing the line in the right place — not "queries take views, mutators take flags", but argument versus
receiver: `union`, `inter`, `diff` and `copyFrom` all mutate their receiver and only read their argument, so all four
now take views. `inter` was the one that could not simply be re-typed, since `retainAll` needs a `Collection`, and its
replacement had to keep answering the narrow "was a flag actually cleared" question its Javadoc promises and C's own
`flag_inter` does not. Two read-only sites in `Player` were unblocked by the change, and a reflection test now fails if
a mutator is ever added to the interface.

### The redraw flags needed a third option that neither instinct offered

Returning the live set and returning a read-only copy both looked reasonable until `redraw_stuff` was read properly: C
takes a snapshot, narrows its own copy when the map is not on screen, acts, then clears from the live set only the bits
it handled. A view breaks the narrowing step and a wipe drops any flag raised mid-repaint, so neither instinct survived.
`getRedrawFlags` now hands back a deliberately mutable snapshot the caller owns and `clearRedrawFlags` takes a
difference, which is C's four steps one for one. Worth carrying forward that `update_stuff` does *not* work this way —
it tests and clears one flag at a time against the live field — so the two sets should not be made symmetrical for
tidiness.

### A view is not an immutable value, and saying so changed three comments

The distinction surfaced from a question about `copyFrom` and turned out to matter in several places: a `FlagView`
withholds mutation from whoever holds the view, but says nothing about whoever holds the underlying `Flag`. Where the
underlying set is final and never written after construction — the `TimedEffect` constants — the view alone is enough
and the defensive copies were dropped. Where it changes constantly, as the upkeep's pending redraws do, the copy is
still what provides a stable value. Three Javadoc blocks that described copies which no longer happen were corrected as
the code moved under them.

### Ninety-five tests were written for the parts that changed

Nine test classes, covering the widened mutators through view-typed references, the band-selection rule and all of its
guards, the snapshot-and-difference contract, the two registry lookups, and the two hand-transcribed C tables. Several
are guarding decisions rather than behaviour — the interface's method list, the no-copy choice on the enum accessors —
because those are the ones a later tidy-up would undo without any test noticing.

**Suite: 2122 tests, 0 failures. Build green, Javadoc generates clean.**
