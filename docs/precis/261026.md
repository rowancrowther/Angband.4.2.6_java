# Precis — 2026-10-26

## Key points from the day

### PlayerRegistry (lookupPlayerShape(int))

`PlayerRegistry.lookupPlayerShape(int)` finds a player shape by its position, standing in for C's `player_shape_by_idx`, whose only use at load is the shape `EffectAssembler` takes for a `SHAPECHANGE` effect with no sub-type. It sent `"Invalid number %d."` on a miss where C says `"Could not find shape %d!"`, and it had no Javadoc and no tests. Your edit puts C's text in the miss message. The method, the `playerShapes` field, the by-name overload and the class Javadoc now record that file order is C's `sidx` order and that a miss shows the message and returns `null`, while six new `PlayerRegistryLookupsTest` cases pin all nine shipped shapes by position, the two misses, an empty list and the unloaded guard. Whoever ports `effect_handler_SHAPECHANGE` can use this lookup for a stored index.

### EffectAssembler (class, assemble, assembleOne, getExpressions, getWrapperSubType)

`EffectAssembler` turns the `effect:` blocks of every data file into `Effect` objects, standing in for `grab_effect_data` in `init.c` and `effect_subtype` and `effect_value_base_by_name` in `effects.c`. An effect with no `GLYPH` sub-type threw, where C leaves the sub-type at 0, which is `GLYPH_NONE`, and its Javadoc and comments still described a `null` return and soft errors that no longer exist. Your edits make the absent glyph give `GLYPH_NONE` and drop the dead `null` handling. The class, field and four method blocks now record that every failure throws, which kinds fold case, what each kind does for an absent token, and the 261025 deviations on numeric sub-types and dice validation. `EffectAssemblerSubTypeTest` gains tests for the index-0 value of every kind and the case rules, and its glyph test now expects `GLYPH_NONE`, so any later change to a sub-type list has a table to be checked against.

### Test suite (stale tests, MonsterSpell parser)

The suite had 84 failures, 54 of them from `MonsterSpellLexer.java` and `MonsterSpellGrammar.java` being older than the `EffectBlockLexer.g4` and `EffectBlock.g4` they import. The rest were 14 tests that still expected a bad effect to drop a record and 16 that predated `PROJ_MAX`. The two parsers were regenerated with the plugin's jar, the 14 were rewritten to expect the `DataFileParseException` and the effect's own line, and the `ProjectionAssemblerTest` helper now skips `PROJ_MAX`, with `ChannelEnumsTest` and `ElementEnumTest` expecting it. The suite is green at 12,011 tests with 21 skipped. A bad effect line in any reader now stops the load, and the tests say so.

## Things not to drop

- `EffectAssembler.java`: `assemble` still carries `@Nullable` and `@CheckReturnValue`, though it never returns `null` now, and `errors` is passed through `assemble`, `assembleOne`, `getExpressions` and `getWrapperSubType` without being used.
