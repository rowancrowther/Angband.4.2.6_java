# Precis — 2026-10-28

## Key points from the day

### ObjectBaseAssembler.assemble

`ObjectBaseAssembler.assemble` turns each parsed `object_base.txt` record into an `ObjectBase`, standing in for the `parse_object_base_*` handlers in `obj-init.c` and the zeroed `kb_info` slot that `finish_parse_object_base` leaves for tval 0. The last assembler in the object-base chain still carried the soft-error contract in its Javadoc and in 13 tests, although the code had already moved to C's behaviour: a bad tval, flag or number ends the load, an unknown colour is white, `IGNORE_` sets the ignore bit, an absent number is 0 and the sentinel has no name. A clause-by-clause check found no mismatch, so the port is unchanged. The class, logger and `assemble` Javadoc now record the fatal paths, the prefix rule of `grab_element_flag`, the `NONE` and `MAX` flags, the sentinel and the clamped-number deviation, and a new `ObjectBaseAssemblerTest` of 109 cases pins each branch while 13 reader and domain tests that pinned the old behaviour were rewritten. Anything that reads a base's name must now expect `null` for a record with no plural part, as C's `NULL` name does.

### ObjectPropertyAssembler.assemble

`ObjectPropertyAssembler.assemble` turns each parsed `object_property.txt` record into an `ObjectProperty`, standing in for the `parse_object_property_*` handlers in `obj-init.c`. Like the object-base assembler it still described soft errors in its Javadoc and in 16 tests, although the code already stops the load on a bad type, subtype, id-type, code, tval or number, and the old tests wrongly said C has no flag `MAX`. The check found one real difference: the grammar's `type-mult:` map was unordered, so two spellings of one tval could resolve in any order. The grammar now keeps the lines in file order, which leaves a single narrow case (a repeated spelling after an alias) recorded in `docs/Accepted_Deviations.md` and pinned by a test. The class, logger and `assemble` Javadoc now record the fatal paths, the table each code reads, the valid flag `NONE` and `MAX`, the absent-code defaults and the two deviations, and a new `ObjectPropertyAssemblerTest` of 109 cases replaces the stale `ObjectPropertyAssemblerTypeTest` while 10 reader tests were rewritten.

## Things not to drop

- `ColourEnum.java` (`fromCode`): `graphics:shade` resolves to `COLOUR_SHADE`, where C's `color_table` has only 28 populated rows and no row for it.
- `ObjectPropertyGrammar.g4` and `ObjectPropertyParseRecord.java`: a record that repeats `bindui:` keeps only the last line, where C binds every line; no shipped record repeats it.
- `ObjectPropertyGrammar.g4` and `ObjectPropertyAssembler.java`: a `bindui:` above `code:` binds the final code, where C binds the index held when the line is read; no shipped record is ordered that way.
