# Precis — 2026-10-23

## Key points from the day

### Artifact.copy

`Artifact.copy` is the port of C's `copy_artifact` in `obj-randart.c`, which copies the whole struct, gives the copy its own brand, slay and curse arrays, and sets the copy's `activation` and `alt_msg` to `NULL`. The Java copy had carried the activation and message across, and threw on a `null` curse map where C keeps a `NULL` curse array as `NULL`, though the class itself treats `null` as valid. `copy` now leaves the activation and message `null` and copies a `null` curse map as `null`. Four copy tests that expected the activation to be carried across were rewritten to C's behaviour, `ArtifactCopyCursesTest` covers the null, empty and populated curse maps, and the full suite is green.

### ArtifactAssembler and ObjectKind.setLevel

`ArtifactAssembler` builds each `Artifact` from `artifact.txt` and makes the kind for a special artifact, the work of the `parse_artifact_*` handlers and `write_dummy_object_record` in `obj-init.c`. C gives a new special kind the artifact's level as it stands when `base-object:` is read, so the 14 shipped special kinds are level 0, but the Java kind had taken the artifact's final level. The grammar now records whether a `level:` line came before `base-object:` and the level at that point, and the assembler passes that to the new `ObjectKind.setLevel`. A record with two `base-object:` lines is an accepted deviation, the Javadoc in `ArtifactAssembler`, `ArtifactParseRecord` and `ObjectKind` now says how the level is chosen, and `ArtifactKindLevelOrderTest` pins nine line orders against C with the full suite green.

### BlowEffectAssembler

`BlowEffectAssembler` builds each `BlowEffect` from `blow_effects.txt`, the work of the `parse_eff_*` handlers in `mon-init.c`. It had rejected an unknown single-letter lore colour that C reads as white, read `power:` and `eval:` in decimal where C's `strtol` takes a leading `0` as octal, matched element resists case-sensitively, and left the flag resist unset so the file did not compile. The colours now fall back to white as C's two colour lookups do, the integers go through `HelperFunctions.parseIntString`, and element names are upper-cased before lookup. The Javadoc now walks each field against C, seven `BlowEffect` tests that pinned the old skip-and-continue and null defaults were rewritten to C's values, eighteen new reader tests cover the colour, integer, resist and lash cases, and the full suite is green.

## Things not to drop

- `ObjectKind.java`'s artifact constructor still copies `artifact.getLevel()`, which `ArtifactAssembler` always overwrites, so the level is set in two places.
- `ArtifactAssembler.java` stops the load on a record with no `base-object:`, where C keeps it with tval 0; this is part of the Stage 7b name-only-records item.
- `grammars/BlowEffectLexer.tokens` is stale: it lists `lore-colour-immune:` where `BlowEffectLexer.g4` says `lore-color-immune:`, so a parser generated against it carries the wrong literal name.
