# Precis — 2026-10-27

## Key points from the day

### MonsterBase (wideMonsterChar, getWideMonsterChar, isWideChar)

`MonsterBase` holds the default glyph of a monster family, standing in for the `wchar_t d_char` of `struct monster_base` in `monster.h`. A Java `char` cannot hold a code point above `0xFFFF`, and `MonsterBaseAssembler.java` rejected such a glyph, so a modded `monster_base.txt` with one would not load. Your new `wideMonsterChar` field and its two accessors split the glyph the way `AngbandDisplayCharacter` does, and the first draft of the assembler had the halves the wrong way round, which the new `noGlyphInTheRealFileIsWide` test caught on all 56 shipped bases. The assembler now puts a glyph up to `0xFFFF` in the narrow half and a supplementary one in the wide half, and the class, field, constructor and accessor Javadoc record the split and that C has no counterpart. Callers that need every glyph must check `isWideChar()` before trusting `getDefaultMonsterChar()`, and 9 new tests plus a rewritten astral reader test pin the boundaries at `0xFFFF` and `0x10000`.

### MonsterBaseAssembler.assemble

`MonsterBaseAssembler.assemble` turns each parsed `monster_base.txt` record into a `MonsterBase`, standing in for the `parse_mon_base_*` handlers in `mon-init.c`. It was the last assembler in the soft-errors-to-fatal sweep with a skip-and-continue branch, so a bad race flag dropped one base and let the other 55 load, where C stops the whole load, and it returned the bases in file order where C's chain runs from `Morgoth` back to `ancient dragon`. Your change makes an unknown flag throw `DataFileParseException` naming the flag, line and file, and puts each base at the front of the list. The class, logger and `assemble` Javadoc now record the fatal paths, the glyph split, the pain lookup and the reversed order, and the reader tests that assumed file order or a skipped record were rewritten, with new ones for `NONE`, `MAX`, a bad flag mid-list, pain serial 0 and a mixed narrow and wide glyph pair. The assembler now never writes to its `errors` list, and any caller that indexes the result by file position must count from the end.

- `MonsterBase.java`: `toString` leaves out `wideMonsterChar`.
- `docs/Assembler_Issues.md`: the `monsterbase/MonsterBaseAssembler.java` glyph section still says a glyph above U+FFFF is a soft error, and it names a test that was renamed.
