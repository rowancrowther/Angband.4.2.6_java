# Precis — 2026-09-09

## Key points from the day

### `SwingUI.JPanelArea.erase` and
`Window.erase` documented and covered, giving the row-blanking screen primitive a verified base

`erase` blanks a run of cells in one row of the character grid, the port of C's `Term_erase`, with `Window.erase`
the thin wrapper that reaches the panel and repaints once the row is updated - the same two-step shape
`Window.clear()` already uses. It's one of the handful of screen primitives the birth roadmap's D2 stage calls a shared
dependency: any screen the game draws needs it, not just birth's. The first two verification passes each caught the
out-of-range guard checking the wrong one of the grid's two dimensions against `x` and `y` - first missing entirely,
then checking each coordinate against the other's bound - before a third pass matched C's
`Term_gotoxy` guard exactly. Two new test suites, one for the panel and one for the window wrapper, pin the ordinary
run, the width clamp at the row's edge, the zero- and negative-length no-ops, and all four out-of-range coordinates, so
the primitive the rest of D2's screens will build on now has a settled, checked shape underneath it.
