# Precis — 2026-11-15

## Key points from the day

### ObjPropertyType.fromValue and lookup

`ObjPropertyType` is the enum of object-property categories, and `fromValue` stands in for the `streq` chain in `parse_object_property_type` in `obj-init.c`. `fromValue` matched C on every token walked through, but the Java-only `lookup` had no C counterpart and compared constant names against data-file tokens, so it could never match and then broke the build while being mended. It now matches on the constant's own name, with or without the `OBJ_PROPERTY_` prefix, and a null name returns null as `fromValue` does. The class, `logger` and `lookup` Javadoc now say the two lookups differ on purpose, since `lookup` resolves `NONE` and `MAX` where `fromValue` refuses them, and `ObjPropertyTypeTest` pins both. Anything that later needs to go from a constant name to a category can use `lookup`, while data-file parsing must keep to `fromValue`.

### ObjectProperty

`ObjectProperty` is the port of `struct obj_property`, one record of `object_property.txt`, and it can now be built whole by the full constructor or blank by the no-argument constructor and filled line by line. Every field and every pricing rule matched `obj-properties.h` and the `parse_object_property_*` handlers in `obj-init.c`, but the Javadoc had fallen behind the code: three fields said they had no accessor, `getBoundEntries` said the list was fixed at construction, and nineteen members had no block at all. The class, fields and every member are now documented, with the two construction routes and their `""`-versus-`null` difference for an absent text line spelled out. `ObjectPropertyBlankRecordTest` pins the blank-record defaults, `type_mult` defaulting to 1, last-line-wins and `bindui:` order against the C handlers, and the stale `ObjectPropertyTypeWrapperTest` case that expected the NONE wrapper to be refused now asserts that it is built. Whoever wires `ObjectProperty2Assembler` into the reader gets a documented, tested target to build against.

### TValue

`TValue` is the enum of object type values and the port of `obj-tval.c`: the `tval_is_*` and `tval_can_have_*` predicates, `tval_find_idx`, `tval_find_name` and the two kind counters, with the constants following `list-tvals.h`. Every constant, predicate and lookup matched C, but `lookup`, the port-only method that finds a constant by its identifier, had no Javadoc and nothing said how it differs from the identifier step inside `fromName`. `lookup` is now documented, as are a C quirk where `strtoul` wraps a very large negative number into range and the class's mention of it, and `TValueConstantLookupTest` pins `lookup` and that wrap. Anything that later reaches for `lookup` has its contract written down, while data-file text must keep going through `fromName`.

### ElementEnum

`ElementEnum` is the port of the `ELEM_*` list in `list-elements.h`, with the base, high and resistable flags standing in for the ordinal ranges `object.h` delimits, and `lookup` standing in for the `element_names` search in `grab_element_flag`. The constants, their order and the three flags all matched C, but `lookup` now puts a missing `ELEM_` prefix on its argument, so the bare C name finds the element and the whole constant name does too, which the Javadoc still said was refused. The class and `lookup` blocks now describe the three steps (add the prefix if absent, exact match, otherwise `null`), and `ElementEnumLookupTest` gained a case pinning that the bare form is still matched exactly. Callers can pass either form, while the placeholders `ELEM_NONE` and `ELEM_MAX` still have to be refused by whoever parses data files.

### ObjectModifier

`ObjectModifier` is the port of C's `OBJ_MOD_*` enum, built from `list-stats.h` and then `list-object-modifiers.h`, and `lookup` stands in for `code_index_in_array` over the `obj_mods` table. The constants and their order matched C, but `lookup` returned the `OM_NONE` and `OM_MAX` sentinels and took an optional `OM_` prefix where C's table holds only the sixteen bare names, and nothing in the Javadoc or the tests said so. Both differences are accepted deviations and are now written on `lookup` and in the class block, and `ObjectModifierTest` pins every bare name at C's index, the prefix, the sentinels, and the case, blank and null refusals. Callers such as `ObjectProperty2Assembler` can rely on `lookup` returning a sentinel and must keep refusing it themselves.

### ObjectFlag

`ObjectFlag` is the port of C's `OF_*` list in `list-object-flags.h`, with `lookup` standing in for the object flag name table searches in `lookup_flag` and `code_index_in_array`, and `getSustainStatFlag` for `sustain_flag`. The 38 constants, their labels and their order all matched C, but `lookup` takes an optional `OF_` prefix and finds `NONE`, where the class, `OF_NONE` and `lookup` blocks said the prefix was refused and `NONE` never matched. Both differences are accepted deviations (261115); the three blocks now say so, and `ObjectFlagTest` gained a case pinning that a null sustain stat throws. Callers such as `ShapeAssembler` can rely on `lookup` returning the sentinels and must keep refusing them themselves.

## Things not to drop

- `ObjectPropertyTypeWrapper.java`: the modifier constructor's Javadoc still says `type` must be stat or mod, but it also builds the NONE wrapper.
- `ObjectPropertyReader.java`: still runs `ObjectPropertyAssembler`, so `ObjectProperty2Assembler` and the blank-record route have no live caller yet.
- `PlayerTimedAssembler.java`, `BlowEffectAssembler.java`, `EgoItemAssembler.java`, `PlayerRaceAssembler.java`: build elements with `ElementEnum.valueOf`, bypassing `lookup`, so `ELEM_NONE`/`ELEM_MAX` are accepted and a bad name throws; not yet judged against C.
- `ObjectProperty2Assembler.java`: refuses the `OM_NONE`/`OM_MAX` sentinels with an "illegal sentinel" message, where C reports any such code as an unknown name.
- `ShapeAssembler.java`: builds object flags with `ObjectFlag.valueOf`, bypassing `lookup`, so `OF_MAX` is accepted and a bad name throws; not yet judged against C.
- `Monster.java`: the `objFlag != OF_NONE || objFlag == OF_MAX` test looks malformed (already noted in its Javadoc).
