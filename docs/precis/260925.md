# Precis — 2026-09-25

## Key points from the day

### UIPlayer.getUIEntryLabel verified and ported

A `/port` pass targeted `UIPlayer.getUIEntryLabel`, the label formatter the resistance-panel layout calls while building
the character sheet. The first verify pass found two real discrepancies against C's `get_ui_entry_label`, both since
fixed by Rowan: a missing `length == 0` no-op guard and an off-by-one in the padding count.

A re-verify this session found both fixed and matching C clause for clause, so nothing further needed changing in
`UIPlayer.java`.

Full Javadoc was written for the class, its two static fields (`firstCallOfGetEntryLabel`, `spc`)
and the method itself, plus a new `GetUIEntryLabel` nested group in `UIPlayerTest` with nine cases derived from the C
branches — the no-op guard, the empty-buffer case, both padding sides, the
`MAX_SHORTENED + 1` cutoff on both sides of its boundary, truncation, and the exact-width edge. The full suite is green.

The resistance-panel label formatter now has documentation and regression coverage tying it to its C original, so a
future change to padding or truncation there will be caught immediately.

### UIPlayer.configureCharSheet verified and ported

A `/port` pass targeted `UIPlayer.configureCharSheet`, the method that builds the resistance-panel layout the previous
entry's label formatter feeds into. The first verify pass found the layout's supporting data classes, `CharSheetConfig`
and `CharSheetResist`, did not have anywhere to hold more than one resist entry per panel region, which crashed or
silently dropped data depending on which region ran; several iterations were needed to reshape that storage correctly.

`CharSheetResist`'s label became a plain string instead of a fixed array, and `CharSheetConfig` picked up a proper
per-region, per-entry lookup so every matching entry in a region is retained rather than only the last one written. A
re-verify walked the method against C clause by clause once that settled and found it matching throughout.

Full Javadoc was written for the method, its `CharSheetConfig`/`CharSheetResist` fields and helper predicate, and both
supporting classes in full, plus a new `ConfigureCharSheet` nested group in
`UIPlayerTest` covering region layout, the stat-modifier and row-fit clamps, and the multi-entry retention the fix was
about. The full suite is green.

The resistance panel can now correctly display more than one resistance, ability, hindrance or modifier per region — the
whole point of the panel — where before it silently could not, so future work building the actual on-screen rendering
has a layout cache to trust.
