## Key points from the day

### C source locations for the sidebar/monster-health/character-sheet split, and where every PlayerEventStatusUpdate field goes

A research pass (no code touched) traced the three classes the `260926_change_in_architecture_from_cache_to_messages.md`
design doc names — the sidebar, the monster health bar, and the character sheet — back to their exact C originals, then
matched every value `PlayerEventStatusUpdate.java` currently caches to one of the three. `SidebarModel` was re-read as
it stands today (HP/SP pairs plus the name/title/race/class quartet, `frontend/ui/SidebarModel.java`);
`MonsterHealthModel`
and `CharSheetModel` don't exist as files yet.

The sidebar's values come from two tables in `ui-display.c`: `side_handlers[]` (:822-849) and the `player_events[]` list
that drives it (:67-84) through `update_sidebar` (:863), plus the parallel status-line pair `status_handlers[]`
(:1321-1322) and `statusline_events[]` (:86-94) through `update_statusline`/`update_statusline_aux` (:1325-1348). The
monster health bar is `monster_health_attr` (:378) and `prt_health`/`prt_health_aux` (:439/:484) — one entry inside
`side_handlers[]` in C, but the design doc carves it into its own model because its shape (a record of one health pair
plus seven timed-effect flags) doesn't fit the sidebar's plain rows. The character sheet is the `display_panel` family
in
`ui-player.c`: `get_panel_topleft` (:705), `get_panel_misc` (:841), `get_panel_midleft` (:719), `get_panel_combat` (:
741)
and `get_panel_skills` (:792), rendered by `display_panel` (:592) off the `panels[]` table (:863-871), plus the
stat-bonus breakdown `display_player_stat_info` (:455) and the sustain-grid sizing in `display_player_sust_info` (:527).
None of the character-sheet functions runs off a `PR_*` flag — C reads `player` fresh whenever the sheet is opened,
matching the design doc's note that the character sheet doesn't fit `redraw_stuff`.

**→ SidebarModel** (a `side_handlers`/`status_handlers` function reads it): `playerTitle` (`prt_title` :200),
`raceName`/`className` (`prt_race`/`prt_class` :571/:595), `level`/`maxLevel` (`prt_level` :213, `max_lev` sets the
colour), `experience`/`maxExperience` (`prt_exp` :233, `max_exp` sets the colour), `gold` (`prt_gold` :264),
`currentHP`/`maxHP` (`prt_hp` :325, already wired), `currentSP`/`maxSP` (`prt_sp` :344, already wired), `armourClass`
(`prt_ac` :311 — the combined `ac+to_a` figure), `speed` (`prt_speed`/`prt_speed_aux` :524/:490), `currentStats`/
`maxStats`/`statsString` (`prt_str`/`int`/`wis`/`dex`/`con` :565-569 via `prt_stat` :157), `equipSlotCount`
(`prt_equippy`
:278, `player->body.count`), `depth` (`prt_depth` :549, `fmt_depth` reads `player->depth`, current level only),
`studyStatus`/`studyConditions` (`prt_study` :1250), `detectionStatus` (`prt_dtrap` :1230), `restingRepeatStatus`
(`prt_state` :977), `levelFeeling` (`prt_level_feeling` :1074), `lightLevel` (`prt_light` :1151). `playerName` also
belongs here in practice — it's already wired via `EVENT_PLAYER_NAME` — even though no `side_handlers` row prints a Name
row; C's only Name reader is the character sheet's top-left panel, so this one is sidebar-hosted but charsheet-sourced.

**→ MonsterHealthModel**: `monsterHealth`/`maxMonsterHealth` (`mon->hp`/`maxhp`), `monsterVisible`,
`playerHallucinating`
(`player->timed[TMD_IMAGE]`), `monsterTracked` (`player->upkeep->health_who`), and the seven `monTmd*` flags (`Fear`/
`Disen`/`Command`/`Conf`/`Stun`/`Sleep`/`Hold`, `mon->m_timed[MON_TMD_*]`) — all read together by
`monster_health_attr` (:378) and `prt_health_aux` (:439).

**→ CharSheetModel**: `bodyCount` (`display_player_sust_info`'s array sizing, :527, a second copy of
`player->body.count`
distinct from the sidebar's `equipSlotCount` copy of the same C field), `isPlaying`, the five stat-bonus arrays
`raceStatBonuses`/`classStatBonuses`/`equipStatBonuses`/`totalStatBonuses`/`currentStatBonuses`
(`display_player_stat_info`
:455, the RB/CB/EB/Best columns), `totalWeight`/`weightLimit` (`get_panel_midleft`'s Burden/Overweight rows, :719),
`expToLevel`/`expFactor` (`show_adv_exp`, feeds `get_panel_midleft`'s Adv Exp row), `height`/`weight`/`age` and, more
surprisingly, `turn`/`totalEnergy`/`restingEnergy` (all six from `get_panel_misc` :841 — Turn/TotalEnergy/RestingEnergy
carry the `PlayerStatus*` name today but no sidebar function ever reads them), and the ten combat fields `toA`/`toD`/
`toH`/
`meleeSkill`/`shootSkill`/`bthPlusAdj`/`meleeDice`/`meleeSides`/`numBlows`/`numShots` (`get_panel_combat` :741). Two
more
`PlayerStatus*`-named fields turn out to be charsheet-only the same way: `maxDepth` (`show_depth`, feeds
`get_panel_midleft`'s Max Depth row — `fmt_depth` in the sidebar's own `prt_depth` never touches `max_depth`, only
`player->depth`).

The pattern worth keeping: where one C global feeds both a `side_handlers` row and a `get_panel_*` row (Level, Exp,
Gold, AC, Speed, body count), C reads the single shared `player` struct twice; the Java port can't do that once the two
values live in separate model classes with no shared memory, so `PlayerEventStatusUpdate` already carries that C value
as two independently-named fields (one per model) today, and that split should carry over unchanged rather than being
collapsed back into one.

### Port verification of SideHandler, HandlersHolder.prtRace and SidebarModel's shapechanged accessors

A port-check pass compared `SideHandler`, `HandlersHolder`'s `prtField`/`prtRace`/`initHandlers`, and
`SidebarModel`'s `playerIsShapechanged` field/accessors against their C originals in `ui-display.c`. Every clause
matched — struct layout, the clear-then-write field sequence, the branch order for the shapechanged case, and the
`side_handlers[]` table entry — except that the shapechanged flag itself has no writer anywhere in the port yet, so
`prt_race`'s field-blanking branch is currently unreachable. Javadoc across all three files now records that gap as a
deliberate Outstanding note rather than a bug, and a new test suite (`SideHandlerTest`, `HandlersHolderTest`, plus an
addition to `SidebarModelTest`) exercises the shapechanged branch directly through the package-private setter, proving
the branch itself correct ahead of whatever eventually wires a real signal into it. Whoever picks up the shapechange
effect port next has both the exact gap in the boundary to fill in and a passing test that already expects the
blanked-field behaviour once it's connected.

### Javadoc for the level and title-row wiring, and a stale "no writer yet" note superseded

Today's pass wrote Javadoc for the character-level and title-row wiring across `HandlersHolder`, `RedrawRouter`,
`SidebarModel` and `Player` - the level/wizard/winner/shape-name fields and their accessors, `prtLevel`/`prtTitle`/
`prtClass`/`fmtTitle`, `setPlayerLevel`, and `Player`'s experience and wizard/winner/max-level readers, all coded
without Javadoc until now. A stage-1 verify ahead of the Javadoc caught three bugs first: an unregistered sidebar row, a
wizard-mode string in the wrong punctuation, and a title-formatting bug that would crash on any string shorter than its
buffer, plus a missing null guard that would have thrown the first time the title row redrew with no shape set. Rowan
fixed all four; re-reading the surrounding code afterward also showed the shapechanged flag already has a real writer
end to end, so the "no writer yet" note this file recorded earlier today has been superseded rather than left standing.
The level and title rows are now documented, tested and green as a matched set, so the shapechange effect's own port
inherits working plumbing instead of a stub.
