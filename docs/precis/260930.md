# Precis — 2026-09-30

## Key points from the day

### Javadoc, tests and stamps for the whole of `Chunk.java`

The whole of `Chunk.java` went through the port pass against `cave-square.c`, `cave-view.c`, `cave.c`, `cave-map.c`,
`mon-make.c`, `obj-pile.c` and `game-world.c`, leaving out the block waiting on Chapter 6. It found four divergences:
`Feature.isRock` answered C's granite question where four `Square` predicates needed the `TF_ROCK` flag, a new chunk
started with every grid lit and occupied, `Square.trapTimeout` stopped at the first trap, and `objectDelete` left the
object in its pile. Until they were fixed, permanent walls, rubble and secret doors failed `isPerm`, `isRubble` and
`isSecretDoor`, which fed `squareChangeable`, `squareIsDiggable` and `squareIsStrongWall`. Rowan added
`Feature.fullRock`, zeroed the constructor's squares, fixed the timeout scan and made `objectDelete` excise the object
from its owning pile, and the Javadoc for `caveMonster`, `objectDelete`, `resetNoise` and `getNoise` now matches the
code. `SquareTerrainClassTest` runs fourteen terrains from `terrain.txt` through six rock predicates against C's
definitions, the pile and construction cases are pinned, and two `ChunkSquareForgetTest` cases that predated the
per-chunk current level were updated. `resetNoise` is now a stub with its C-derived test disabled, so its port only
needs that test enabled.

### `ClockwiseDirectionLoop`, the ring behind `clockwise_ddd[]` and `clockwise_grid[]`

`ClockwiseDirectionLoop` is the Java form of the two clockwise direction arrays in `cave.c`, which the `MOVE_ATTACK` and
`SWEEP` effect handlers walk to turn a heading or scan the eight neighbours. It had no callers yet, but it could never
have worked: the cursor was never set, and the singleton could not be reached from outside the class. Rowan built the
ring once as a static field and gave each `new ClockwiseDirectionLoop()` its own cursor starting at north, so the ring
matches the C arrays entry for entry, centre included, and any number of loops run without affecting each other. Future
callers create a loop wherever C would hold an index, and must skip the centre entry that C's modulus-eight walk never
reaches.
