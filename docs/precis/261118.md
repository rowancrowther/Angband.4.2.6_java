# Precis — 2026-11-18

## Key points from the day

### BlowEffect

`BlowEffect` is the Java form of C's `struct blow_effect`, the record that `blow_effects.txt` fills one directive at a time. Its no-argument constructor, which `BlowEffect2Assembler` starts every record from, left the lash null where C's zeroed `lash_type` 0 names the ACID projection, and its Javadoc still described an immutable class with null colours. A record with no `lash-type:` line (only `NONE` in the shipped file) would have handed a null projection to the lash effect and the lash spell message, where C lashes with acid, and the class, the `projectionResist` field, both constructors and the setters were undocumented or wrong. The constructor now looks up the ACID projection, and the class, its twelve fields, both constructors and every accessor carry full Javadoc. Building a `BlowEffect` now needs the projections loaded (an accepted deviation), so tests that assemble records seed them first, and a lash reader can use `getLashType()` without a null check except for `lash-type:MAX`.

### QuestAssembler

`QuestAssembler`, `QuestParseRecord`, `Quest` and `QuestGrammar.g4` are the Java form of C's `parse_quest_name`, `parse_quest_level`, `parse_quest_race` and `parse_quest_number` in `player-quest.c`. The grammar now groups lines the way C does (`name` first, then any mix of `level`, `race` and `number`), but the assembler's guard against a directive ahead of its `name` tested the directive's own name, so it could never fire, and the first fix to it would have thrown a `NullPointerException` on the very case it was meant to catch. The guard now tests the quest's own name, so a hand-built record that opens with `level`, `race` or `number` is refused with a message naming the directive and its line, which is the "where C crashes, Java throws" rule decided today. The class blocks, five private directive methods, five setters and the grammar header now describe the real shape, and the stale claims that all four directives are mandatory and that `Quest` has no setters are gone. Quest loading now has tests for the guard (three directives, a late name, a second record, the boundary), the whole-line name and the wrong value counts, and `emptyQuestFile` in `WorldDataLoaderTest` now expects the empty list C loads.

### VaultAssembler

`VaultAssembler` is the Java form of C's `parse_vault_name`, `parse_vault_type`, `parse_vault_rating`, `parse_vault_rows`, `parse_vault_columns`, `parse_vault_min_depth`, `parse_vault_max_depth`, `parse_vault_flags` and `parse_vault_d` in `generate.c`, turning `vault.txt` records into `Vault`s. Its zero `max-depth:` rewrite stored the world's maximum depth as it came, where C stores it in a `uint8_t` and so narrows it, and its class and `assemble()` Javadoc still described a fixed check order the file-order handlers no longer follow. The zero branch is now narrowed like every other depth, so a world maximum above 255 loads as in C, and the class, `assemble()` and all eleven private handlers carry full Javadoc. Vault loading now has tests for an unknown `type:` that is never checked, and for a later `type:` replacing an earlier one before `rows:`, and `DungeonLoaderTest` now feeds the grammar a file that opens without `name:`, the only grammar error left once every directive after `name:` became optional.
