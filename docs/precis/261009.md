# Precis — 2026-10-09

## Key points from the day

### `ObjPropertyType.fromValue` and `ObjectPropertyAssembler.assemble` checked against `parse_object_property_type` in `obj-init.c`

`fromValue` turns the `type:` token of an object property into its category, and `assemble` uses it to pick the table the `code:` resolves against. Because the lookup walked every constant, the placeholder tokens for `OBJ_PROPERTY_NONE` (empty) and `OBJ_PROPERTY_MAX` ("max") resolved to real categories, where C rejects both as an invalid property. `fromValue` now returns null for both and the assembler reports an empty type as "has no type", matching C's missing-type error. `ObjPropertyTypeTest` and `ObjectPropertyAssemblerTypeTest` pin the seven real tokens, the two placeholders and the near-misses ("resist", "Stat"), and show a bad record leaving its neighbours intact. The Javadoc on the enum, its constants and its fields now says which tokens a data file can name, so later work on object-property data can rely on the category never being NONE or MAX.

## Things not to drop

- `ObjectPropertyAssembler.java`: the `default` branch of the category `switch` can no longer be reached, and if it ever were it would add the record with a null index rather than dropping it.
