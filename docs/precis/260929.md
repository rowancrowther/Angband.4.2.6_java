# Precis — 2026-09-29

## Key points from the day

### Javadoc and tests for the EVENT_MONSTERHEALTH sidebar row

Today's pass finished the port of the sidebar's monster health bar - C's `prt_health`, `prt_health_aux` and
`monster_health_attr` - covering the new `EventDataMonsterInfo` payload, `eventSignalMonInfo`, the `PR_HEALTH` arm in
`PlayerCalcs.redrawStuff`, `RedrawRouter.setMonsterHealth`, the twelve monster fields on `SidebarModel`, and the drawing
logic in `HandlersHolder`. A verify pass caught that the healthy colour at 100 per cent was `COLOUR_GREEN`
where C uses `COLOUR_L_GREEN`, and `HandlersHolderTest` still counted seventeen side-handler rows. Rowan fixed the
colour and the new `HealthBarTest` pins the star-count thresholds, colour boundaries and timed-effect override order to
C's values, with the stale row-count test updated to twenty. The row is now documented, tested and green, so the next
sidebar rows, speed and depth, inherit both the twelve-field payload pattern and its test template.

### Javadoc and tests for the EVENT_PLAYERSPEED sidebar row

The sidebar's speed row - C's `prt_speed` and `prt_speed_aux` - now runs on the message path, through the new
`EventDataPlayerSpeed` payload, `eventSignalPlayerSpeed`, the `PR_SPEED` arm in `PlayerCalcs.redrawStuff`,
`RedrawRouter.setPlayerSpeed`, four `SidebarModel` fields and the drawing in `HandlersHolder`. The verify pass matched C
clause by clause, and the extract-energy table in `ChannelRegistry` matches `game-world.c` across all 200 entries. The
new
`SpeedRowTest` pins the blank, offset and multiplier forms, the truncation and the row's priority to C's values, and the
two row-count tests that predated the row were updated to twenty-one. Only `prt_depth` is left in the table, and the
next dispatcher port must draw this row only on its own event, because the model starts at speed zero.
