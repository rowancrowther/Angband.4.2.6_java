# Precis — 2026-10-26

## Key points from the day

### PlayerRegistry (lookupPlayerShape(int))

`PlayerRegistry.lookupPlayerShape(int)` finds a player shape by its position, standing in for C's `player_shape_by_idx`, whose only use at load is the shape `EffectAssembler` takes for a `SHAPECHANGE` effect with no sub-type. It sent `"Invalid number %d."` on a miss where C says `"Could not find shape %d!"`, and it had no Javadoc and no tests. Your edit puts C's text in the miss message. The method, the `playerShapes` field, the by-name overload and the class Javadoc now record that file order is C's `sidx` order and that a miss shows the message and returns `null`, while six new `PlayerRegistryLookupsTest` cases pin all nine shipped shapes by position, the two misses, an empty list and the unloaded guard. Whoever ports `effect_handler_SHAPECHANGE` can use this lookup for a stored index.

### EffectAssembler (class, assemble, assembleOne, getExpressions, getWrapperSubType)

`EffectAssembler` turns the `effect:` blocks of every data file into `Effect` objects, standing in for `grab_effect_data` in `init.c` and `effect_subtype` and `effect_value_base_by_name` in `effects.c`. An effect with no `GLYPH` sub-type threw, where C leaves the sub-type at 0, which is `GLYPH_NONE`, and its Javadoc and comments still described a `null` return and soft errors that no longer exist. Your edits make the absent glyph give `GLYPH_NONE` and drop the dead `null` handling. The class, field and four method blocks now record that every failure throws, which kinds fold case, what each kind does for an absent token, and the 261025 deviations on numeric sub-types and dice validation. `EffectAssemblerSubTypeTest` gains tests for the index-0 value of every kind and the case rules, and its glyph test now expects `GLYPH_NONE`, so any later change to a sub-type list has a table to be checked against.

### Test suite (stale tests, MonsterSpell parser)

The suite had 84 failures, 54 of them from `MonsterSpellLexer.java` and `MonsterSpellGrammar.java` being older than the `EffectBlockLexer.g4` and `EffectBlock.g4` they import. The rest were 14 tests that still expected a bad effect to drop a record and 16 that predated `PROJ_MAX`. The two parsers were regenerated with the plugin's jar, the 14 were rewritten to expect the `DataFileParseException` and the effect's own line, and the `ProjectionAssemblerTest` helper now skips `PROJ_MAX`, with `ChannelEnumsTest` and `ElementEnumTest` expecting it. The suite is green at 12,011 tests with 21 skipped. A bad effect line in any reader now stops the load, and the tests say so.

### HistoryAssembler (class, logger, assemble)

`HistoryAssembler.assemble` turns the `chart:`/`phrase:` records of `history.txt` into linked `PlayerHistoryChart`s, standing in for `parse_history_chart`, `findchart` and `finish_parse_history` in `init.c`. It had thrown on every repeated chart number, so no shipped chart with more than one entry could load, it accepted a negative chart number and it rejected none of C's chart 0. Your edits find or create the chart by number, refuse a leading `-` on the chart number, and throw when a repeat names a different successor or a successor names no chart. The class, the `logger` field and `assemble` now record that every failure throws, that one successor per chart is the deviation from C's per-entry `isucc`, and what a bad value does. `HistoryReaderTest` swaps its five stale tests for ones that expect the `DataFileParseException`, and gains cases for chart 0, `-0`, a successor of -1, a forward and a self successor, a same-successor repeat in file order and octal `010`. The suite is green at 12,018 tests with 21 skipped, and a history file that varies a chart's successor now stops the load, where C would load it.

### ItemObjectAssembler (class, logger, assemble)

`ItemObjectAssembler.assemble` turns the records of `object.txt` into `ObjectKind`s, standing in for the `parse_object_*` functions in `obj-init.c`. It dropped every curse, rejected `HATES_` flags, read the `alloc:` range in base 0 where C reads it in base 10, and its glyph constructor stored every glyph in the wide half so a basic glyph never equalled the `char`-built cell. Your edits store curses of power above 0, give `IGNORE_` and `HATES_` each their own bit, read the range in base 10, build the glyph through the existing constructors, and make an absent `pval:` zero and a bad one throw. The class, field and method blocks now record the fatal policy and each C-derived rule, and `ItemObjectReaderTest` swaps its twelve skip-and-continue tests for ones that expect the `DataFileParseException`, with assembler-level cases for glyphs, the white fallback, `pval:` and `alloc:`. `ItemObjectAbsorbPartialTest` now seeds an empty curse list so `new Player()` can build its `KnownObject`, which leaves the suite green at 12,031 tests.

### MonsterAssembler (class, logger, assemble) and ParseUtils (onlySpaceAndTab)

`MonsterAssembler.assemble` turns the records of `monster.txt` into `MonsterRace`s, standing in for the `parse_monster_*` functions in `mon-init.c`, and `ParseUtils.onlySpaceAndTab` stands in for `contains_only_spaces` in `z-util.c`. `spells:MAX` and `message-*:MAX` were refused where C accepts them, a negative `depth:` threw where C stores it, and the class and method Javadoc still described soft errors and dropped records. Your edits accept the `MAX` spell row and tag the last of `depth:` and `spell-power:` so only a `spell-power:` line refuses a leading minus, and the class, field, `assemble` and `onlySpaceAndTab` blocks now record the fatal policy, each C-derived rule and the five accepted deviations. `MonsterReaderTest` and `MonsterAssemblerFrequencyTest` swap their stale skip-and-continue tests for ones that expect the `DataFileParseException`, with new cases for the sentinel rows, spell power, blank messages and an absent base, and a new `ParseUtilsOnlySpaceAndTabTest` covers the helper; the suite is green at 12,094 tests with 21 skipped. A bad `monster.txt` record now stops the load, and the colour-cycle, line-order, second-base, `same`-friend and overwritten-`spell-power:` deviations are recorded in `Accepted_Deviations.md`.

## Things not to drop

- `EffectAssembler.java`: `errors` is passed through `assemble`, `assembleOne`, `getExpressions` and `getWrapperSubType` without being used.
- `HistoryReader.java`: the class Javadoc and the `parseWithResults` Javadoc still describe a soft error for a dangling or non-uniform successor, where `HistoryAssembler.java` now throws.
- `PlayerHistoryChart.java`: the `successor` field Javadoc still says the assembler records an error and leaves `null` for an unresolvable successor, where it now throws.
- `docs/Assembler_Issues.md`: the `history/HistoryAssembler.java` section still describes soft errors, decimal reading and a negative chart loading, and none of it holds now.
- `docs/Accepted_Deviations.md`: it has no History entry for the one-successor-per-chart throw.
- `HistoryAssembler.java`: `errors` is not used, and the dangling-successor message has no "starting at line" because a chart does not keep its line.
- `ItemObjectAssembler.java`: the `InvalidTokenFoundDuringParse` import is no longer used.
- `ItemObjectReader.java`: the class and `parseWithResults` Javadoc still describe a skipped record and soft errors for a bad tval, flag, brand, slay or figure, where `ItemObjectAssembler.java` now throws.
- `MonsterReader.java`: the class and `parseWithResults` Javadoc still speak of soft errors, where `MonsterAssembler.java` now throws.
- `MonsterParseRecord.java`: the new `spellPowerOrDepth` component has no `@param` line.
- `MonsterLexer.g4`: `COLOUR_CHAR` takes only the 28 colour codes, so an unlisted letter or a colour name is a syntax error where C loads white.
