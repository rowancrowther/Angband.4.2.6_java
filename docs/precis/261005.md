# Precis — 2026-10-05

## Key points from the day

### `Curse` tests migrated onto the curse's own object after the unflattening

Your unflattening moved a curse's weight, flags, modifiers, element info, combat figures, effect, message and known
figures onto `curse.getItemObject()` and slimmed the constructor to seven arguments, which left 144 compile errors
across 15 test files and stopped the whole suite from running. `CurseFixture` now builds the object and passes it to the
new constructor, giving it and its known twin a bare kind so `hasStandardToH` reads the to-hit as it does at runtime,
and the other test files read and write through `getItemObject()` and `getKnown()`. `CurseGetTimeTest` became
`CurseObjectTimeTest` because `Curse.getTime()` no longer exists, and `CurseKnownStateTest` now pins the known object's
setters in place of the removed `known*` ones. The suite is green again at 7383 tests with no failures, so the remaining
unflattening steps can be checked against it.

### `Curse` checked against `struct curse` and its functions in `obj-curse.c`, `obj-knowledge.c` and `obj-init.c`

`Curse` is the Java form of C's `struct curse`, with the nested `curse->obj` flattened into fields, and it carries the
ported `modify_weight_for_curse()`, the curse arms of `object_has_standard_to_h()` and `object_fully_known()`, and the
read of `curse->obj->time`. All four matched C on every branch and boundary I walked through, so no code changed. The
class, every field, the constructor and every method now carry Javadoc that names the C counterpart, and four blocks
lost their C line numbers. The new `CurseWeightBoundariesTest` and `CurseKnownStateTest` pin the strict comparisons in
the weight arithmetic, the copy-versus-store behaviour of the known-view setters and the null time of an effect with no
`time:` line, so later ports that call `Curse` can lean on all of it.

### `MessageTag.getTag` checked against `msg_tag_lookup()` in `obj-util.c`

that names
`obj-util.c` and records that argument difference, and `MessageTagTest` gained cases for the opening-letter rule and the
sizes, so the activation and artifact messages that use the tags can rely on it.

### `RandomValueUtils` checked against `Rand_div()`, `Rand_normal()`, `Rand_sample()`, `damroll()`, `damcalc()`,

## Things not to drop

- Curses are numbered from 0 in `CurseAssembler.java` and `ObjectRegistry.curseMax` is the count, where C leaves slot 0
  as a dummy and `curse_max` is the count plus one, so decide the convention before porting the random curse picks in
  `effect-handler-general.c` and the wizard curse command, or `vulnerability` will never be chosen.
- `GameWorld.java` and `ObjectUtils.java` now read a curse's timing from `curse.getItemObject().getTime()`, but
  `CurseAssembler.java` writes no time onto that object, so every real curse rolls a timeout of zero until the move in
  `Effect_time_migration.md` lands.
- `Effect.java` has no `equals`, so `ItemObject.effectIsKnown` compares effects by identity as C compares pointers, and
  adding one would turn the "equal but distinct effect" case in `CurseIsFullyKnownTest` from not-known to known.
- Step 5 of `Curse_object_unflattening.md` is still to do: the Javadoc in `Curse.java`, `CurseSource.java`,
  `BonusSource.java` and `PlayerKnowledge.java` still describes a flattened curse.
