## Key points from the day

### Javadoc, bug fixes and tests for the EVENT_EXPERIENCE sidebar row

Today's pass finished the port of the sidebar's experience row - C's `prt_exp` - covering the new
`EVENT_EXPERIENCE` payload types, the dispatching arm in `PlayerCalcs.redrawStuff`, the routing in
`RedrawRouter`, the fields it lands in on `SidebarModel`, and `HandlersHolder.prtExp`'s own drawing logic. A stage-1
verify ahead of the Javadoc pass caught three real bugs in the `redrawStuff` arm in quick succession - the wrong field
sent as the maximum-experience half of the payload, an off-by-one in the next-level threshold lookup, and a level-fifty
case that always displayed zero - plus a follow-on compile error and a `NullPointerException` that only surfaced once
the full test suite ran; two pre-existing tests, `PlayerRedrawStuffTest` and `HandlersHolderTest`, also turned out to
carry counting assumptions that predated this row and needed updating once it existed. Rowan fixed the source bugs
iteratively while Claude re-verified each pass against C and the port's own established `getOrDefault` convention for
reading `PlayerRegistry.playerExperience`, then wrote the Javadoc and updated both stale tests once the suite was green.
The row is now documented, tested and green as a matched set, with one deliberate divergence recorded above for later -
so the next sidebar row to be ported inherits a template for both the payload-carrying-event pattern and the test
coverage that pins it.

### Bug fix and test repair for UIPlayer.cnvStat's cap branch

Today's fifth pass closed out the `cnvStat` bug surfaced incidentally by the stat-row work above: the
`bonus >= 220` branch that should collapse to the literal `"18/***"` cap sat outside the `bonus >=
100` check as a separate, unconditional `if`, so the cap was always overwritten by the three-digit branch a line below
it before anything could read it. Rowan turned the two into a single
`if`/`else if`/`else` chain matching C's `cnv_stat`, and Claude re-verified the boundary and ordinary values (18, 92,
100, 220 and a stat below 18) against C directly before signing the fix off. The existing `UIPlayerTest.CnvStat` suite
already carried the right expectations for every branch, but had drifted out of sync with `cnvStat`'s own signature and
was failing on a reflection
`NoSuchMethodException` rather than exercising the bug - that call was updated to the current two-argument method, and
the suite (along with `DisplayPlayerStatInfo`, which reads the same cap through `displayPlayerStatInfo`) is green again
without any new test cases needed. The character sheet's stat-modifier columns can now be trusted to show the same
figures C would past a bonus of 220, which they could not before.

### Bug fix, Javadoc and tests for the sidebar's armour-class row

including expanding an existing handler-registration test to all fourteen table rows; running the full suite in the
process also resolved the `PlayerRedrawStuffTest` NPE and its follow-on stale dispatch-count assertion flagged in an
earlier pass's "Things not to drop", since both needed exactly the fixture state this row's own test work supplied. The
suite is green, and the sidebar's armour-class row is now complete, tested and documented for the next row to follow the
same shape.

## Things not to drop

### PlayerRedrawStuffTest.everyFlagMapsToItsCEvent NPEs on a missing PlayerState stub

`PlayerCalcs.redrawStuff`'s `PR_STATS` arm reads `player.getPlayerState().getStatUse(stat)`, but this pre-existing
test's fixture player has no `PlayerState` set up, so the test NPEs as soon as `PR_STATS`
is exercised alongside the other flags. It predates the stat rows' own addition and was not touched during that pass,
since it lives outside `HandlersHolderTest`'s and this test's own already-updated counting assumptions. Needs a
`PlayerState` stub added to the fixture before this test goes green again.

### EVENT_EXPERIENCE's two dispatches share one event type, for now

`PlayerCalcs.redrawStuff`'s `PR_EXP` arm sends `eventSignalLongStat` and `eventSignalLong` both under
`GameEventType.EVENT_EXPERIENCE`, rather than giving the second dispatch its own type the way `PR_MISC` gives
`EVENT_PLAYER_NAME` alongside `EVENT_RACE_CLASS`. Rowan has chosen to keep it this way for the time being, so
`RedrawRouter.setExperience` stays a pattern-match-on-payload-shape router rather than a plain per-type one, and
`PlayerRedrawStuffTest`'s `everyFlagMapsToItsCEvent`
now expects the repeated dispatch explicitly rather than treating it as a bug. Worth reconsidering later: splitting the
pair onto two event types would let both that method and its test drop the special-casing.
