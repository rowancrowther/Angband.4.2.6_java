# Precis — 2026-10-30

## Key points from the day

### TerrainFeatureAssembler.assemble

`TerrainFeatureAssembler.assemble` turns each parsed `terrain.txt` record into a `Feature`, standing in for the `parse_feat_*` handlers and the look-string half of `finish_parse_feat` in `init.c`, and has been reworked from soft errors to fatal ones. The rework also has to handle a repeated `code:` the way C does, by filling the same `f_info` slot: text lines append, flags add up, `graphics:` replaces, the single-value lines replace only when present, and a second name is fatal. The check found seven differences along the way (every first record throwing on a name check, a lost later name and description, a feature mimicking itself, the old glyph kept, absent digging refused, and look strings joined after their space), which you fixed with a new `Feature.getMimicTerrainFlags()` and a second pass for the trailing space. The class, logger and `assemble` Javadoc now record the fatal paths, the repeated-code merge, the `NONE` refusal for flags and the 261027 priority clamp, and 58 assembler tests plus 13 reader and loader tests were rewritten to the fatal model. Code that loads terrain can no longer expect a partial list or a lowered `store_max` after a bad record, and the merge for a repeated code is reachable only from hand-built records while the grammar requires `name:` on every record.

### Feature

`Feature` is the port of C's `struct feature` in `cave.h`, with the `feat_is_*` predicates and the flag halves of the `square_is*` tests from `cave-square.c`, re-checked after the assembler rework. Every predicate and field still matches C, but four Javadoc blocks described the old code: the shop number was credited to the assembler, the display character was said to be possibly null, and `equals` and `hashCode` called the enum `resistFlag` an identity comparison. Those blocks were rewritten and Javadoc was added to the nineteen undocumented accessors, with five new tests covering the zero shop number before loading, every accessor, the live flag set, the look setters and the broken door. A missing message now reads as the empty string and a missing resist flag as `RF_NONE`, where C has NULL and 0, and later chapters that test for an absent message should test for empty rather than null.

### TrapAssembler.assemble

`TrapAssembler.assemble` turns each parsed `trap.txt` record into a `TrapKind`, standing in for the `parse_trap_*` handlers and the `tidx` numbering of `finish_parse_trap` in `init.c`, and has been reworked from soft errors to fatal ones. The check found it matching C throughout, including the `NONE` and `MAX` flag refusals that C gets from `lookup_flag` starting past slot 0, but the class and `assemble` Javadoc still described skip-and-continue, accepted sentinels and a blank display character in white, and eight reader and loader tests still expected records to be dropped or sentinels to load. The Javadoc was rewritten for the fatal model and 39 new assembler tests were added, with the eight old tests rewritten to expect the throw. Code that loads traps can no longer expect a partial list or closed-up indices after a bad record, and an absent `graphics:` line still differs from C only in drawing a space where C has `'\0'`.

## Things not to drop

- `TrapReader` class Javadoc still says a negative `appear:` value and `flags:MAX`/`save:MAX` load, that a missing `graphics:`/`visibility:` gives `null`, and that a bad effect is kept with a `null` list; all are now fatal or zeroed in `TrapAssembler`.
