# Precis — 2026-10-15

## Key points from the day

### `TextBlock` checked against `textblock_append_textblock`, `textblock_calculate_lines` and `textblock_to_file` in `z-textblock.c`

`TextBlock` is the Java form of C's `struct textblock`, a run of coloured characters that is appended to, wrapped and written to a file. The wrapping loop, the appends and the indent padding already matched C, but appending a block to itself threw a `ConcurrentModificationException` where C doubles the text. `append(TextBlock)` now snapshots its argument with `copy()` first, so the self-append matches C. `toFile` clamps a negative indent to zero where C would wrap wider; that is recorded as an accepted divergence in its Javadoc, since no caller passes one. The class, fields and every method now carry Javadoc with the C cross-reference, and `TextBlockTest` pins the wrapping cases, quirks included, so the `ui-output.c` and character-dump ports have a tested block to build on.

### `Quit.quit` checked against `quit` in `z-util.c`

`Quit` is the Java form of C's `quit()`: log a message and end the game, or leave silently when the message is `NULL`. It had no clean-quit case, so `ControlUtils.quit()` logged a fatal empty line and the crash handlers in `Main` treated every quit as a failure. `quit(null)` now logs nothing and throws a `GameQuitException` with no message, which both handlers in `Main` read as a clean quit with exit status 0. `MainTest`'s crash tests set `Main.debug` by reflection so the handlers' `System.exit` does not end the test JVM, and `QuitTest` pins the clean-quit and failure cases against C's contract, so a later change to either side of the exit handling will show up there.

### `AngbandModule` checked against `struct init_module` in `init.h` and the module loops in `init.c`

`AngbandModule` is the Java form of C's `struct init_module`, the name, `init` and `cleanup` triple that `init_angband()` and `cleanup_angband()` walk over the `modules[]` roster. The interface already matched C, including the forward, non-reversed cleanup order, but its Javadoc cited C line numbers that had drifted and implied that some 4.2.6 modules lack one half of the pair when all fourteen supply both. The class and all three methods now carry Javadoc that names the C files and functions instead, and `AngbandModuleTest` pins the three-member shape, the forward walk for both halves, the empty-half implementor and `Quark` as the one conforming module. The roster and its two loops are not ported yet, so that test states what they must do and will be the first thing to check them against.

## Things not to drop

- `TextBlock.java`: there are no accessors for the text and colours of a single cell, so `textblock_text` and `textblock_attrs` have no counterpart beyond `toString`, and the `ui-output.c` port will need per-cell access.
- `TextBlock.java`: nothing in `src/main` calls `calculateLines` or `toFile` yet, so `object_info_chardump`, `object_info_spoil` and `textui_textblock_show` have nothing to call.
- `Main.java`: both crash handlers identify a clean quit by `getMessage() == null` rather than by `GameQuitException`, so any other message-less `RuntimeException` would exit with status 0 and no log.
- `Main.java`: both handlers call `System.exit` straight after posting the shutdown message, so nothing waits for the other half and the UI `finally` never runs; the `Main` Javadoc now describes this rather than denying it.
- `ControlUtils.java`: `quit()` is still described as taking a "blank quit string" though it now passes `null`, and every quit helper hard-wires `new Quit()`, so `QuitAux` is never swapped as C's `quit_aux` is.
