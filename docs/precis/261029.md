# Precis — 2026-10-29

## Key points from the day

### PlayerPropertyAssembler.assemble

`PlayerPropertyAssembler.assemble` turns each parsed `player_property.txt` record into a `PlayerProperty`, standing in for the `parse_player_prop_*` handlers and `finish_parse_player_prop` in `init.c`. Its Javadoc and 12 reader tests still described soft errors and dropped records, although the code already ends the load on a bad code, a code on an `element` record, `code:MAX` on an object, or a bad `bindui` aux or value, and it stores 0 for the `value:` of a non-element record. The check found three error messages that named the wrong field (the element message printed the type, and the `bindui` value messages said `aux`), which you fixed, and the binding order was accepted as a deviation on 261029 (file order, where C binds the last line first). The class, logger, `assemble` and `spreadPlayerPropertyOut` Javadoc now record the fatal paths, the accepted deviations, the unreachable hand-built-type arm and the raw UI-entry names, and 12 reader tests were rewritten and 8 added (75 in all) to pin each branch, with the `-2147483648` deviation marked. Code that reads a binding's order must not assume C's reverse order, and code that reads `getValue()` can rely on 0 for a `player` or `object` property.

### PlayerRaceAssembler.assemble

`PlayerRaceAssembler.assemble` turns each parsed `p_race.txt` record into a `PlayerRace`, standing in for the `parse_p_race_*` handlers and the numbering half of `finish_parse_p_race` in `init.c`. The check found five differences from C: every race carried an index of 0, a missing or unknown history chart stopped the load where C stores a null, the `NONE` and `MAX` sentinels loaded as real flags and resists, a `values:` name lost any four characters instead of needing the `RES_` prefix, and a race with no `stats:` or `skill-*:` line had no entry where C reads 0. You fixed all five and a negative `history:` that the first fix let through, and the class, logger and `assemble` Javadoc now record the fatal paths, the zeroed defaults and the null history, while 16 stale reader tests were rewritten and 6 added (53 in all) to pin each branch. A race's index is now its position in the file, and code that reads a race's stats, skills or history must expect 0 for a missing line and a possible null history.

### PlayerTimedAssembler.assemble

`PlayerTimedAssembler.assemble` turns each parsed `player_timed.txt` record into a `PlayerTimedEffect`, standing in for the `parse_player_timed_*` handlers in `player-timed.c`. The check found that the `fail:` list was stored in file order where C stores it last line first, that a repeated `name:` put the later record's `fail:` lines after the earlier ones instead of in front, and that an absent `desc:`, `on-end:`, `on-increase:` or `on-decrease:` line held an empty string where C holds `NULL`, which got past the `!= null` checks in `PlayerTimed.setTimed`. You fixed all three and `PlayerTimed.incCheck` now walks the stored list as it stands, while the Javadoc records the fatal paths, the merge of a repeated name and the deviations from C, the stale reader, grade and duplicate-name tests were rewritten, and `PlayerTimedAssemblerTest` adds 24 tests for the fields, so the full suite is green. Code that reads `getFail()` can now rely on C's order, and `getDescription()` and the three message getters return `null` when the file gives no line.

### EffectAssembler (assemble, assembleOne, getExpressions, getWrapperSubType)

`EffectAssembler` turns the `effect:` blocks of every data file into `Effect` objects, standing in for `grab_effect_data` in `init.c` and `effect_subtype` and `effect_value_base_by_name` in `effects.c`. A clause-by-clause check against the C found no difference, and the 261026 pass had already settled the sub-type lists. Nothing in `src/main` needed to change, but the Javadoc did not yet say that a number outside the int range is clamped where C wraps it, that a summon or shape resolved before its registry loads throws `IllegalStateException`, or that the timed-effect sub-type refuses `MAX` as well as `NONE`. The class and four method blocks now record those, and a new `EffectAssemblerFieldsTest` of 25 cases pins which sub-type kind each of the 112 effects takes, the base 0 reading of the radius, other parameter, `y` and `x`, the message, the raw dice text, the expression split, and the wording and line number of each failure. A later change to an effect's sub-type kind, or to the order the checks run in, now has a test to be checked against.

### PlayerTimed (setTimed, incCheck, timedGradeEq, playerIncTimed, playerDecTimed, playerClearTimed)

`PlayerTimed` is the behaviour half of `player-timed.c`: `player_set_timed` and the inc, dec and clear routes into it, `player_inc_check` and `player_timed_grade_eq`. A clause-by-clause check found no difference from C, and the existing suites already pinned the bounds, the grade walk, the messages, the veto order and the return value. The one wrong statement was in the `incCheck` Javadoc, which said the walk reverses the list, although the grammar and assembler now store the `fail:` lines in C's order and the loop walks them as stored. The `incCheck`, `setTimed` and `playerDecTimed` blocks and the class block are corrected, and `PlayerSetTimedTransitionTest` adds 24 tests for the begin and end chains (which transition fires each, in list order, before the store, silent or not, with `source_none` or `source_player` by `can_disturb`) and for an effect's own redraw flags. The chain loop now has a test to be checked against when `Effect.effectDo` is ported.

### PlayerTimedEffect

`PlayerTimedEffect` is the record for one `timed_effects[]` entry, the port of `struct timed_effect_data` in `player-timed.h`, with every field and default checked against the C struct, its static initializer, the parser setters and the places C reads each field. A clause-by-clause check found no difference, but the Javadoc said the begin and end effects are null when the file gives none, although the assembler passes an empty list, and it said an exact synonym silences every change, although C still announces a grade change. The class, the two effect fields, `oFlagExactlySyn`, `tempResist`, the brand and slay fields, the constructor and the two effect getters are corrected, and the constructor's stale note about a parameter name is gone. A new `PlayerTimedEffectShippedDataTest` adds 8 tests that sweep all 53 effects of the shipped `player_timed.txt` for message type, non-stacking, lower bound, synonym, resist, brand, slay and effect chains, so a field that lands on the wrong effect now fails a test. Code that reads the begin or end chain can rely on an empty list, and code that reads a message type can rely on `MSG_GENERIC` where the file gives none.

### TimedEffect

`TimedEffect` is the enum of the 53 `TMD_*` rows of `list-player-timed.h`, each carrying the redraw and update flags C lists for it. A clause-by-clause check found no difference: every constant has C's name, order and flags, and `PlayerTimed.setTimed` adds `PR_STATUS` to every notified change as C does. The Javadoc said `TMD_BLIND` and `TMD_IMAGE` do not touch the status line, which is true only of their own sets, and the descriptions of `TMD_AMNESIA`, `TMD_ATT_RUN`, `TMD_BLOODLUST` and `TMD_BLACKBREATH` did not match what C does with them. Every constant, `TMD_MAX`, both fields and the constructor now carry a block and a provenance stamp, the wrong descriptions are rewritten, and `TimedEffectTest` gains tests that pin the 53 C symbols in order, the count, and the exact exceptions to the common flag pair. Anyone reading the sets directly now knows to add `PR_STATUS` themselves.

### ProjectionAssembler.assemble

`ProjectionAssembler.assemble` turns each parsed `projection.txt` record into a `Projection`, standing in for the `parse_projection_*` handlers and `finish_parse_projection` in `obj-init.c`. The Javadoc and 13 of its 32 tests still described skipped records and `errors` entries, although every fault already stopped the load, and the check found one difference from C: an all-digit `denominator:` above `INT_MAX` is clamped where `parse_random` refuses it. You accepted the clamp and it is recorded under Projection in `docs/Accepted_Deviations.md`, the class, `assemble` and four helper blocks now describe the fatal paths, the base 0 reading of the `uint` fields and the base 10 denominator, and `ProjectionAssemblerTest` was rewritten and extended to 40 tests, with six stale `ProjectionReaderTest` cases updated so the suite is green. Code that loads `projection.txt` can rely on a stopped load for any bad field, and on a clamped denominator rather than a refused one.

## Things not to drop

- `PlayerPropertyReader.java`: the class Javadoc still says a `code:` the assembler cannot resolve drops that record with a soft error, and lists a `value:` on a `player` or `object` record as kept, where C drops it; the assembler now stops the load on the code and stores 0 for the value.
- `docs/Assembler_Issues.md`: the `PlayerPropertyAssembler.java` entry (found 2026-10-18) is out of date, since `code:MAX` on an object, a code on an `element` record, an unknown code and an aux of `00` or `-0` now behave as in C, and a `value:` on a non-element record is dropped.
- `PlayerPropertyAssembler.java`: the `value:` read passes an empty token name, so a non-numeric value would read "has an invalid  value"; the lexer only passes digits, so it cannot be reached.
- `PlayerRaceReader.java`: the class Javadoc (the paragraph on race order) says the assembler passes 0 for every race's index, and the `parseWithResults` Javadoc says an unresolved flag, resist or history chart is a soft error that drops the race; the assembler now numbers the races and stops the load.
- `docs/Assembler_Issues.md`: the `PlayerRaceAssembler.java` entry (found 2026-10-18) is out of date, since the race index, the history chart, the sentinels and the resist prefix now behave as in C.
- `PlayerTimedGrammar.g4`: a repeated `desc:`, `on-end:`, `on-increase:` or `on-decrease:` line in one record overwrites where C appends, repeated `on-begin-effect:` and `on-end-effect:` lines overwrite where C adds to the list, and `effect-yx`, `effect-dice`, `effect-expr`, `effect-msg` and the radius and other fields of an effect are not captured.
- `docs/Assembler_Issues.md`: the `PlayerTimedAssembler.java` entry (found 2026-10-19) is out of date, since the down message, `lower-bound:`, unknown `flags:` tokens, the `fail:` order and an `exact` of `00` now behave as in C.
- `Effect.java`: `effectDo` takes one effect where C's `effect_do` walks a whole chain, so `PlayerTimed.setTimed` loops the begin and end lists itself; when `effect_do` is ported in Chapter 6, decide whether the chain walk (the shared `ident` and any early stop) belongs there or at each call site.
- `PlayerSetTimedTest.java`, `PlayerIncTimedTest.java`, `PlayerDecTimedTest.java`, `PlayerClearTimedTest.java`, `PlayerTimedGradeEqTest.java`, `PlayerOfHasNotTimedTest.java` and `PlayerIncCheckTest.java`: the class and group Javadoc still cite `player-timed.c` line numbers, which drift each time a C function in that file is stamped.
- `PlayerTimed.java`: the `!= null` guards around `getOnBeginEffect()` and `getOnEndEffect()` in `setTimed` are always true, since the assembler passes an empty list where C holds `NULL`; harmless, but they no longer test anything.
- `PlayerFlagsTimedTest.java`: the class Javadoc cites `player.c`, `player-calcs.c` and `trap.c` line numbers, which drift each time a C function in those files is stamped.
- `ProjectionAssembler.java`: the `projCode == null` throw after `resolveCode` is unreachable in the element block, since `resolveCode` throws first, and the `< 0` checks after `minusFound` on the numerator, divisor, damage cap, `obvious` and `wake` can never be true.
- `Random.parseStr` and `RandomReader`: the dice form of `denominator:` was not checked against `parse_random`, which refuses any figure above `INT_MAX` in every slot.
- `ProjectionReader.java`: a `record-count:` mismatch is a soft error that is lost when the element rule stops the load, since the exception message carries only the element count.
