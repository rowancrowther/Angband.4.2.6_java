### BuilderType.fromName(String)

`BuilderType` held C's `cave_builders[]` table but had no way to find an entry by name, which `parse_profile_name` in `generate.c` does with a `streq` loop. Until now `DungeonProfileAssembler` could not refuse a profile whose `name:` matches no builder, so Stage 2 item 8 had nothing to call. `fromName` returns the constant whose name matches exactly, or `null`, and its Javadoc records that the caller must turn a miss into `PARSE_ERROR_NO_BUILDER_FOUND`. `BuilderTypeTest` pins every C name at its C index and the misses `streq` would refuse, and the suite is green. The assembler check and a `BuilderType` field on `CaveProfile` can now be written against it.

## Things not to drop

- `DungeonProfileAssembler.java` does not call `BuilderType.fromName`, so an unknown profile `name:` still loads.
- `CaveProfile.java` carries the profile name as a `String` and not a `BuilderType`.
