# Precis — 2026-09-28

## Key points from the day

### Javadoc, bug fixes and tests for the EVENT_EXPERIENCE sidebar row

Today's pass finished the port of the sidebar's experience row - C's `prt_exp` - covering the new
`EVENT_EXPERIENCE` payload types, the dispatching arm in `PlayerCalcs.redrawStuff`, the routing in
`RedrawRouter`, the fields it lands in on `SidebarModel`, and `HandlersHolder.prtExp`'s own drawing logic. A stage-1
verify ahead of the Javadoc pass caught three real bugs in the `redrawStuff` arm in quick succession - the wrong field
sent as the maximum-experience half of the payload, an off-by-one in the next-level threshold lookup, and a level-fifty
case that always displayed zero - plus a follow-on compile error and a `NullPointerException` that only surfaced once
the full test suite ran; two pre-existing tests, `PlayerRedrawStuffTest` and `HandlersHolderTest`, also turned out to
carry counting assumptions that predated this row and needed updating once it existed. Rowan fixed the source bugs
iteratively while Claude re-verified each pass against C and the port's own established `getOrDefault` convention for
reading `PlayerRegistry.playerExperience`, then wrote the Javadoc and updated both stale tests once the suite was green.
The row is now documented, tested and green as a matched set, with one deliberate divergence recorded above for later -
so the next sidebar row to be ported inherits a template for both the payload-carrying-event pattern and the test
coverage that pins it.

### Bug fixes, Javadoc and tests for the EVENT_GOLD sidebar row

Today's second pass finished the port of the sidebar's gold row - C's `prt_gold` - covering the new
`EVENT_GOLD` payload wiring already in place in `PlayerCalcs.redrawStuff`, `RedrawRouter`,
`SidebarModel` and `HandlersHolder`. A stage-1 verify caught two bugs in `HandlersHolder`: the row's
`SideHandler` was built but never added to `sideHandlers`, so nothing ever called `prtGold` to draw it, and the figure
was formatted with the literal string `"$9d"` rather than `"%9d"`, so no gold value was ever substituted in. Rowan fixed
both; Claude re-verified the fixes against C's `"%9ld"`
before continuing. Javadoc was then written for every declaration the row touches across the four files, and tests were
added or extended in `RedrawRouterTest`, `SidebarModelTest` and
`HandlersHolderTest` - including updating an existing table-registration test whose five-row count had been invalidated
by the fix, and a dedicated regression test asserting every built handler is actually registered, so a repeat of "built
but never added" fails loudly rather than silently. The suite is green.

### Bug fixes, Javadoc and tests for the equippy sidebar row

Today's third pass finished the port of the sidebar's equippy row - C's `prt_equippy` - covering the glyph/colour lookup
on `ItemObject` it depends on, the port of C's `object_char`/`object_attr`/
`object_kind_char`/`object_kind_attr`/`use_flavor_glyph`. A stage-1 verify caught two real bugs: `UILoop`
was calling a method `RedrawRouter` never defined, a compile error, and `ItemObject`'s flavour-glyph decision had its
boolean logic inverted, so every unidentified item bar an aware scroll would have shown the wrong glyph. Rowan fixed
both; Claude re-verified the corrected logic against C's condition case by case before continuing. Javadoc was then
written across nine files - including two stale doc counts left behind by the row's own addition, in `HandlersHolder`'s
handler-table description and
`PlayerCalcs.redrawStuff`'s payload count - and tests were added or extended in five files, most notably a new suite
pinning all four (scroll, aware) combinations of the flavour-glyph decision so the inverted condition cannot return
unnoticed. The suite is green at 5622 tests, and the sidebar now has a complete equipment row for the next one to be
built against.

## Things not to drop

### EVENT_EXPERIENCE's two dispatches share one event type, for now

`PlayerCalcs.redrawStuff`'s `PR_EXP` arm sends `eventSignalLongStat` and `eventSignalLong` both under
`GameEventType.EVENT_EXPERIENCE`, rather than giving the second dispatch its own type the way `PR_MISC` gives
`EVENT_PLAYER_NAME` alongside `EVENT_RACE_CLASS`. Rowan has chosen to keep it this way for the time being, so
`RedrawRouter.setExperience` stays a pattern-match-on-payload-shape router rather than a plain per-type one, and
`PlayerRedrawStuffTest`'s `everyFlagMapsToItsCEvent`
now expects the repeated dispatch explicitly rather than treating it as a bug. Worth reconsidering later: splitting the
pair onto two event types would let both that method and its test drop the special-casing.
