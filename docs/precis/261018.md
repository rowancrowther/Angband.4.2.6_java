# Precis — 2026-10-18

## Key points from the day

### `ProjectionReader` checked against the projection parser in `obj-init.c`

`ProjectionReader` feeds `projection.txt` through the grammar and assembler into `Projection` objects, standing in for `init_parse_projection`, `run_parse_projection` and the list-building half of `finish_parse_projection`. It already matched C: all 56 projections load in file order, every field of every one agrees with a table worked out from the upstream file, and a missing file is an `IOException` where C quits. The committed `ProjectionGrammar` and `ProjectionLexer` parser had gone stale against its `.g4`, which names the symbol token `FLAG` where the generated code still said `TAG`, so it was regenerated and two `ProjectionLexerTest` expectations followed the rename. The class, the logger and the three methods now say which C function each stands in for and where the port deliberately differs, and `ProjectionReaderTest` grows from 7 to 32 tests that pin the reader's contract, a 56-row table and each difference found. The seven grammar differences are written up in `docs/grammar_issues.md` and the five assembler ones in `docs/Assembler_Issues.md`, and the silent empty result for a misplaced element is the one to start with, because `loadProjections` then carries on with no projections.
