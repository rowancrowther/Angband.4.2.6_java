# Precis — 2026-11-16

## Key points from the day

### BlowEffect2ParseRecord

`BlowEffect2ParseRecord` is the new ordered parse record for `blow_effects.txt`: a list of `Directive`s, one per line, in file order. It sits beside `BlowEffectParseRecord`, which keeps one final value per field, and nothing reads or writes it yet. It had a two-line block that said nothing about why it is a list, so the Javadoc now records the reason: C's `parse_eff_resist` in `mon-init.c` reads the `effect_type` stored by an earlier line, so `resist:` above `effect-type:` is a different record from the reverse. `BlowEffect2ParseRecordTest` pins the order, a repeated `desc:` and the ten directives `init_parse_eff` registers. The grammar and assembler that fill and read it can follow the `ObjectProperty2` pattern without redesigning the record.

### ProjectionEnum.lookup

`ProjectionEnum.lookup` is the Java counterpart of `proj_name_to_idx` in `project.c`, turning a data-file projection name such as `FIRE` into a constant. It built a prefixed search string and then compared the unprefixed original, so no bare name ever matched and `fire` could not match either, which would have left the new blow-effect assembler's `lash:` and `resist:` tokens resolving to null. The comparison now uses the prefixed string and ignores ASCII case, and the class, `getFromElementEnum` and `lookup` carry full Javadoc. `ProjectionEnumLookupTest` checks all 56 C names in C order, with and without the `PROJ_` prefix and in lower case, plus the `NONE` and `MAX` placeholders and the near-miss inputs. Callers can now pass the bare names straight from the data files and treat `PROJ_NONE` as the one result to refuse.
